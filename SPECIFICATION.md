# Техническое задание: Выпускной проект — Сервис по обработке ГНСС наблюдений

> ГНСС – глобальные навигационные спутниковые системы

## Общие требования

Сервис представляет собой HTTP API со следующими требованиями к бизнес-логике:

- Регистрация, аутентификация и авторизация пользователей
- Приём файлов ГНСС наблюдений в формате RINEX 2.xx / 3.xx от зарегистрированных пользователей
- Обработка ГНСС наблюдений абсолютным методом спутниковой геодезии с использованием открытой программной библиотеки RTKLIB
- Формирование отчёта об обработке, включающего:
  - Оценки координат в пространственной прямоугольной геоцентрической системе координат на эпоху наблюдений
  - Среднеквадратические погрешности наблюдений
- Учёт и ведение списка результатов обработки наблюдений

## Абстрактная схема взаимодействия с сервисом

1. Пользователь регистрируется в сервисе
2. Пользователь загружает на сервис файл наблюдений в формате RINEX 2.xx / 3.xx
3. Файл наблюдений попадает в систему обработки ГНСС наблюдений
4. Система выполняет обработку и связывает отчёт обработки ГНСС наблюдений с пользователем

## Система обработки ГНСС наблюдений

Система обработки ГНСС наблюдений является внешним сервисом в доверенном контуре. Она работает по принципу «чёрного ящика» и недоступна для инспекции внешними клиентами. Внешнему потребителю доступна только информация об оценках координат и среднеквадратических погрешностях.

> Протокол взаимодействия с сервисом базы будет предоставлен отдельно.

## Сводное HTTP API

Сервис должен предоставлять следующие HTTP-эндпоинты:

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| POST | /api/user/register | Регистрация пользователя |
| POST | /api/user/login | Аутентификация пользователя |
| POST | /api/user/observation | Загрузка файла ГНСС наблюдений для обработки |
| GET | /api/user/history | Получение списка отчётов по обработке файлов пользователя |
| GET | /api/user/result/<номер_отчёта> | Получение отчёта с результатами обработки по указанному номеру |
| GET | /api/user/last | Получение последнего отчёта с результатами обработки |

## Общие ограничения и требования

1. Хранилище данных — PostgreSQL
2. Структура таблиц — на усмотрение разработчика
3. Типы и формат хранения данных (включая пароли и другую чувствительную информацию) — на усмотрение разработчика
4. Сервер должен поддерживать HTTP-запросы/ответы со сжатием данных (например, gzip, deflate)
5. Валидация запросов — на усмотрение разработчика
6. Формат и алгоритм аутентификации/авторизации — на усмотрение разработчика
7. Номера отчётов должны быть уникальными и никогда не повторяться

## Конфигурирование сервиса

Сервис должен поддерживать конфигурирование следующими способами:

| Параметр | Переменная окружения | Флаг командной строки |
|----------|----------------------|------------------------|
| Адрес и порт запуска сервиса | RUN_ADDRESS | -a |
| Адрес подключения к БД | DATABASE_URI | -d |

### Примеры запуска

# Через переменные окружения
RUN_ADDRESS=localhost:8080 DATABASE_URI=postgres://user:pass@localhost:5432/db ./service

# Через флаги
./service -a localhost:8080 -d postgres://user:pass@localhost:5432/db

# Комбинированный вариант
RUN_ADDRESS=localhost:8080 ./service -d postgres://user:pass@localhost:5432/db
